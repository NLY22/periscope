# 自主爬取与检索

Periscope 可以在已有搜索、平台和订阅源之外，沿站点结构主动发现资料。爬虫得到的网页正文、PDF 文本、Word 正文和 Excel 单元格进入同一个话题结果、运行记录和语料库，关闭 DeepSeek API 后也能独立工作。

## 两种入口

自动跟进本轮资料：

```text
periscope-topic --topic "人形机器人" --crawl --no-api
```

爬虫优先选择本轮原生直采结果，再使用可用的 API 结果；最多从六个入口开始，优先分散到不同站点。API 关闭时仍使用直采链接。普通查询保持原有耗时范围，只有指定 `--crawl` 或 `--crawl-seeds` 才启用额外爬取。

直接从指定站点开始：

```text
periscope-topic --topic "attention" --crawl-seeds https://arxiv.org/abs/1706.03762 --crawl-pages 6 --crawl-depth 1 --crawl-budget 45 --no-api --speed off --save
```

`--speed off` 关闭原有平台采集；指定的爬虫仍执行。可以把种子替换成院校公告列表、研究机构页面、政府目录或站点地图地址。爬虫从入口发现同一组种子域名内的列表链接、详情链接和 PDF，优先处理话题相关链接与 PDF，也读取 robots 声明的站点地图。站点地图提供 URL 发现，不能保证覆盖该站所有内容。

### 已知字段的公开 GET 表单

对不执行脚本、使用 GET 返回查询结果的表单，可指定一个入口和明确的字段：

```text
periscope-topic --topic "计算机" --crawl-seeds https://example.org/admissions --crawl-field year=2026 --crawl-field major=computer --crawl-pages 4 --crawl-depth 1 --no-api --speed off
```

上面的地址和字段是示例，实际名称和值以站点页面为准。系统只选择包含全部指定字段的唯一 GET 表单，检查必填项及页面中已有的下拉选项，然后优先抓取同站查询结果。结果链接和来源记录保留提交的字段及值；结果页中的链接继续遵守原有同站、robots、页数及时间限制。

当前只发送明确指定的可见字段，不自动携带隐藏字段、密码或其他控件默认值；发现隐藏字段、未指定的可见字段或有名称的提交控件时会将此次查询标为 partial，并将提示保存在结果来源信息中。缺少必填项、下拉值无效、匹配多个表单、表单包含密码或文件上传、仅支持 POST、目标位于站外或查询链接过长时不提交，并在报告中记录原因；跳转后的结果链接超过入库上限时也不会作为完整资料保存。需要 JavaScript、依赖动态下拉选项或登录会话的查询系统尚未支持。查询字段及结果 URL 会保存在运行记录中，使用此入口时应只提供公开、非敏感查询条件。此能力已接入命令行、调查服务和独立 MCP 工具，尚未自动接入多轮调查。

### MCP 调用

`ps_crawl_public` 接收 `topic`、公开入口 `seeds`，以及可选的 `form_fields`（字段名到值的映射）、`max_pages`、`depth`、`budget` 和 `save`。例如：

```json
{"topic":"robot", "seeds":["https://example.org/admissions"], "form_fields":{"year":"2026"}, "max_pages":4, "depth":1, "budget":30, "save":true}
```

返回 `rows`（原文和出处）、`reports`（各页面的状态与原因）和 `stats`。调用限定最多 6 个入口、50 页、5 层和 180 秒，复用同站、公开网络地址和 robots 检查。默认不保存；`save: true` 时先将本次结果作为一个批次写入资料库旁的 `evidence-journal` 目录，再写入 MCP 配置指定的资料库。`storage` 报告写入数量、跳过情况或失败原因；写库失败时已写成的批次仍可恢复。保存后可用 `ps_corpus_search` 检索，但不会自动接入研究会话。示例不代表已验证该网站存在或支持此表单。

MCP 保存的公开网页资料会附带 `object_id` 和 `version_id`，可通过 `ps_evidence_get` 读取指定版本。相同提取内容只保存一个版本并保留各批次观察；提取内容变化产生新版本。首次建立版本表之前会备份数据库到旁边的 `backups` 目录。目前新调查链支持网页和 V2EX 帖子／回复的版本记录，其余平台尚未接入。

新的调查入口可以先运行 `periscope-web`，再使用 `ps_investigation_create` 创建会话、`ps_investigation_submit` 提交本轮、`ps_investigation_status` 逐次读取事件，以及 `ps_investigation_evidence` 查看固定版本；`ps_investigation_stop` 可停止采集，`ps_investigation_list` 和 `ps_investigation_get` 可查找历史调查。它们访问同一个本地后端，默认地址为 `http://127.0.0.1:8790`，可通过 `PERISCOPE_BACKEND_URL` 指定本地 HTTP 地址。后端启动时会重放属于当前资料库的批次，再将遗留活动轮标记为中断；不同资料库的批次不会自动混入。这些工具不同于旧 `ps_research_*` 会话。

本轮不提供入口网址时，会直接把输入内容作为关键词，通过第三方 Sov2ex 索引发现 V2EX 帖子；当前最多查找一页、保存匹配的搜索线索并跟进前三个帖子。搜索、每个帖子详情和回复各占一个 `max_pages` 配额；`depth=0` 只保存搜索线索。请求重试另行计入时间预算。超过跟进上限时标记部分完成。搜索线索与详情版本分别标明，索引可用性和覆盖范围不能代表 V2EX 全站。2026-10-28 使用匿名关键词 `python` 和独立资料库进行一次在线验证，保存 2 条搜索线索、2 条帖子详情及 1 条回复；单次样本不代表长期可用或完整覆盖。当前尚不具备自动匹配其他平台或网页对话接入。

配置现有模型 API 后，调查轮采集结束会尝试生成一份简答，在 `ps_investigation_status` 及对应 HTTP 状态的 `answer` 中返回；编号引用保存为固定资料版本，可用 `ps_investigation_evidence` 回查。模型请求包含本轮问题、调查主题、历史指令、采集状态和最多 20 条资料，每条正文最多 3000 字符；这些内容会发送给所配置的外部模型服务。系统优先选择完整正文与回复，并附资料的讨论覆盖情况；状态中的 `collection` 独立记录本轮采集是否完整。回答最多等待 60 秒，超时、模型异常或引用编号无效时标记失败，已采资料仍可查看。未配置模型时 `answer` 为 null；无可用证据时标记 unavailable。模型可能误解资料，引用编号有效不保证每个判断都得到支持。网页尚未展示新调查回答。

本轮采集前会按关键词从本地其他调查轮次的已保存资料中匹配最多 8 条历史版本，先通过事件显示并继续采集新资料；简短追问缺少关键词时使用调查主题。资料和回答引用中的 `origin` 标明来自哪次调查、哪一轮及采集时间；已复用的相同版本再次采到时会发出 `evidence_refreshed` 事件。指定入口时历史匹配限定在入口网站；无入口时本轮默认限定 V2EX。历史搜索采用词面匹配，并非语义检索，只扫描最多 2000 条去重且匹配词面的候选，可能漏掉相关资料；不会自动搜索未与调查轮关联的旧版资料。旧资料的观察时间不代表本轮已更新。

当本轮唯一入口是 `https://www.v2ex.com/t/<帖子编号>` 时，新调查链会匹配 V2EX 适配器，取得正文和有限回复；主题与每条回复分别保留原生编号、版本、采集覆盖和所属关系。讨论内容在全文库可检索，不作为作者事实声明。该接入目前通过隔离接口样本验证，尚未重新进行在线验证；其他平台尚未接入这一新调查链。

需要恢复这些批次时，指定目标资料库和批次目录：

```text
python -m periscope.evidence.journal --corpus /path/to/corpus.db --journal /path/to/evidence-journal
```

恢复会跳过已经入库的相同记录；损坏批次不会被删除，并在输出中列出。命令仅恢复这些批次里的采集资料，不恢复调查会话、草稿或旧版资料库中其他来源的数据。批次目前在整个 MCP 爬取完成后生成，还不是逐页落盘；进程在爬取结束前中断时不能保证保留已取资料。

## 当前提取能力

- HTML：提取正文、表格的可读文本，发现详情、分页和附件链接；正文最多 60,000 字符。
- PDF：提取文本层，每份最多读取 40 页，保存页码、文本范围及 `#page=N` 链接；扫描页标记为需要 OCR，不生成不存在的正文。
- Excel `.xlsx`：按工作表和原行号提取非空单元格，保留例如 `B2=365` 的坐标和值；每行在文档元数据中保存工作表名、行号及文本范围。最多读取 20 个工作表、5,000 行、128 列和 60,000 字符，超限标记 partial。压缩包展开后超过 40 MiB 或包含超过 4,096 项时拒绝解析。公式保留表达式，不执行计算。
- Word `.docx`：按原顺序提取正文段落和表格行，并在文档元数据中记录段落编号、表格编号、行号与文本范围。最多读取 5,000 个段落或表格行、每行 128 个物理单元格及 60,000 字符；Office 压缩包展开后超过 40 MiB 或包含超过 4,096 项时拒绝解析。检测到未提取的页眉、页脚、脚注、尾注、批注、文本框、结构化内容或嵌套表格时标记 partial，并给出原因。
- 站点地图：支持 `urlset` 和 `sitemapindex`，在深度、页数和队列上限内继续发现页面。
- 普通文本：读取文本内容；不执行网页脚本。

大型站点的“入口 → robots 声明地图索引 → 子地图 → 文章”需要 `--crawl-depth 3`；也可以直接把子地图作为入口。默认两层可能只完成地图发现。

每条资料保留入口、父页面、发现深度、观察时间、正文所属 URL、文档类型及原始内容 SHA256。相同 URL 的内容字节发生变化时，显式入库会保留不同版本。当前保存的是提取文本与内容指纹，不是原始网页或 PDF 的完整归档；字节变化也可能来自页面模板，尚未自动判断是否为实质改动。

PDF 页码、Word 段落与表格行、Excel 工作表与行号等文档信息贯穿 JSON、运行分片、入库和历史检索。HTML/PDF/Word/Excel 解析在可终止的子进程中执行，网络预算结束时不会等待仍在解析的文档。已有成功资料在内部预算超时或某页失败时保留，使用者中断进程前未完成的运行不保证已经落盘。

## 范围与结果

默认最多尝试 12 个页面、跟进两层，独立时间预算 30 秒，每份响应最多 5 MiB。页数上限包含失败和未匹配页面；robots 请求与跳转另计入请求数。网络逐主机限速，并遵守 robots 和其 crawl-delay；重定向同样检查域名、公开网络地址和目标路径的 robots。

爬虫不把列表里出现一个关键词就当作已取得全部资料。只有提取的标题或正文匹配话题时才形成检索记录。链接发现、正文为空、需要 OCR、格式不支持、失败、限制阻止、超过大小或预算，均在 `crawl_reports` 中单独记录。汇总状态区分空结果、失败和部分成功。

`--crawl-budget` 与原有 `--budget` 分别限制爬虫和原生平台采集，均不包含 API、本地检索与可选视频富化。正文提取不等于事实核验；发现路径和相同 URL 的多个版本不构成独立信源。

## 验证

2026-10-19，在不调用搜索 API 的情况下，从公开的 `https://arxiv.org/pdf/1706.03762` 提取到 39,613 字符论文文本，并保存逐页位置。结果位于 `.periscope-scratch/crawler-pdf-live-20261019.json`。另一次 20 秒预算的双入口查询保留了已完成的摘要页，把未完成 PDF 记录为超时。

测试覆盖列表到详情/PDF、robots 声明地图中的未直接链接页面、逐页定位、解析子进程取消、边界限制、不同版本保存及再次检索。它们证明自主采集链路可用；未据此宣称上述公开论文是某个搜索 API 无法检索的独家资料。

最终全项目测试 1,341 项通过，其中本轮新增爬虫测试 22 项。安装包在源码目录之外通过真实本地 HTTP 页面、PDF 子进程、显式保存、出处检索和不同版本保存的完整验证。

当前尚未实现扫描件 OCR、旧版 `.xls` / `.doc`、合并单元格和跨行表头的语义恢复、跨站无限递归、通用浏览器渲染或登录会话接管。Word 未提取的页眉、页脚、脚注、尾注、批注、文本框和嵌套表格仅报告缺口；Excel 输出保留原始单元格位置，不自动推断跨行表头或将录取数值解释为结构化结论。已有小红书、抖音等平台适配继续走独立模块。后续平台扩展应以真实漏检样本和新增有效证据衡量。
