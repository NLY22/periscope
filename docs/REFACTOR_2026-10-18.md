# 重构记录（2026-10-18）

## 一、做了什么

三件事：

1. **整理目录** — 45 个散落在根目录的脚本按职责分成四层
2. **接入 DeepSeek Search API** — 它能做得更好的地方直接用它的
3. **采集并发化** — 串行 74.8 秒压到 4.7 秒

### 目录变化

| 之前 | 现在 |
|---|---|
| 45 个脚本全在根目录 | 根目录 1 个入口 |
| `research.py` | `core/search.py` |
| `collector.py` / `collect_http.py` | `collectors/` |
| `ingest_all.py` / `login_*.py` | `tools/` |
| 22 个一次性探测脚本 | `probes/`（归档） |
| 17 处硬编码 `ROOT` | `core/paths.py` 统一管理 |

### 新增

- **`core/paths.py`** — 统一路径与职责边界。现在只有它知道文件在哪，也只有它知道「哪些平台该自己做、哪些交给 API」。
- **`core/dsapi.py`** — DeepSeek Search/Fetch 封装，含 5 QPS 限流与错误处理。
- **`core/merge.py`** — 多源合并 + 跨站去重。这是 API 做不到的事。
- **`collectors/fanout.py`** — 并发采集。串行 74.8 秒 → 并发 26.1 秒，快速模式 4.7 秒。

### 删除

- `research.py`（功能已迁至 `core/search.py`）
- 六个旧版浏览器采集器（`collect_ugc*.py`、`platform_search.py`、`deep_search.py`、`recipes.py`）——被 `collect_xhs/douyin/kuaishou` 取代

## 二、为什么这么分工

分工不是拍脑袋，是逐平台实测出来的。

### 决定依据

对 39 个平台做了 `site:` 限定查询，看 API 返回的**是否真内容**：

| 判定 | 平台 |
|---|---|
| **API 完全搜不到** | 小红书、YouTube、V2EX、Reddit、天涯、B站专栏 |
| **API 只有壳层** | 抖音（10/10 是「相关视频」）、B站（7/10 带 `_bilibili` 后缀）|
| **API 有但陈旧** | 快手（39 条全在某一天）、抖音（停在 2 月）|
| **API 覆盖良好** | 微博、知乎、CSDN、掘金、虎扑、头条、雪球、豆瓣等 28 个 |

### 关键发现

**API 的平台数据是快照，不是实时。**

```
抖音  50 条 → 日期跨度 2026-02-01 ~ 2026-03-10
快手  39 条 → 全部集中在 2026-07-09
微博  20 条 → 最新 2026-10-16
```

对比我们的：

```
微博  近 2 天 6,770 条（含 2026-10-18 当天）
抖音  317 条，带点赞数
```

**且 API 拿不到任何互动数据**（赞/播放/评论全为 False）。

## 四、去重逻辑

这是 **API 做不到**的能力，也是最容易出错的部分。

### 问题

API 的 50 条结果里，同一条新闻被多家转载时算作多条：

```
新浪财经×3、凤凰网×3、百度百科×3
```

### 三种转载形态与处理

| 形态 | 例子 | 处理 |
|---|---|---|
| 加站点名后缀 | `…聚焦钠电新机遇__经济网_国家一类新闻网站` | 归一化清掉后缀 |
| 标题自我重复 | `…走向应用场 - …走向应用场` | 检测前后半段重合，截断 |
| 前置修饰句 | `可以凌空飞踢！中国人形机器人走上世界舞台` | **归一化前**按标点切段，取最长段 |

第三种最关键：归一化会删掉标点，之后再切就找不到分界了。必须在原始文本上切。

### 验证

5 个用例，5/5 正确：

```
OK   合并   '中国人形机器人走上世界舞台' | '中国人形机器人走上世界舞台'
OK   合并   '环球人物年度盛典分论坛聚焦钠电新机遇经济' | '…聚焦钠电新机遇'
OK   合并   '首批人形机器人国标来了' | '首批人形机器人国标来了'
OK   不同   '完全不同的两个标题甲' | '完全不同的两个标题乙'
OK   合并   '钠离子电池加速从实验室走向应用场' | '钠离子电池…应用场'
```

## 五、踩过的坑

### 1. 移动文件后 `ROOT` 未定义

第一轮把 `sys.path.insert(0, r"D:\work\periscope")` 换成 `str(ROOT)`，
但那些文件里 `ROOT` 是在后面的「路径常量」区定义的，模块加载时就 NameError。
第二轮修：删掉过早的 insert，在 `ROOT` 定义之后补上。

### 2. 采集分片路径变了

`ingest_all.py` 原本用 `ROOT.glob()` 扫分片，但新分片写在
`.periscope-scratch/shards/`。改成同时扫两处（`DATA_DIRS`），
重构期间新旧共存不丢数据。

### 3. 平台内容进不了结果

修完 API 接入后发现 Top 10 全是 API 结果，平台采到的当天微博一条也进不来。

原因：API 的 `authority=4` 得 1.0 分，平台行只有 `trust=0.6`。

修法：给平台/本地行加**新鲜度加成**（24 小时内 +0.12，3 天内 +0.06）。
理由是平台数据的独特价值就是「现在正在发生」。

### 4. 无正文的条目排第 3

`google_news` 的行 trust 高但没有正文，排在能读的文章前面。
修法：排序时先按「是否有正文」分档。
