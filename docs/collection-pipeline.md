# 当前采集链路与边界

更新时间：2026-10-24。

## 实际流程

```text
话题指令
  → 本地资料检索
  → 可选搜索 API
  → 按来源条件并发 HTTP 采集
  → deep 模式按需调用平台浏览器
  → 可选网页 / 文本 PDF 爬取、视频文字与 HN / GitHub / V2EX / Stack Overflow / CSDN 讨论富化
  → 合并展示，并由 CLI 保存原始查询记录
  → --save / 显式导入
  → 作者正文与社区讨论分层
  → SQLite / FTS5
  → 可选补正文、缓存回填
  → 再次检索
```

`TopicService.search()` 负责单轮组合，CLI 负责保存查询记录和显式入库；直接调用服务方法并不自动持久化。网页与 MCP 仍使用既有研究编排，尚未完整接入新版话题采集。

`--enrich` 可对 HN story 搜索结果按 `objectID` 跟进 Firebase 评论树，可读取 GitHub issue 评论和 PR 行内 review 评论，将 V2EX 搜索结果跟进到主题正文和回复，也能读取 Stack Overflow 题目正文、热门答案及题目／答案评论，并从 CSDN 博客搜索命中获取正文和评论树。CSDN 最多尝试 3 页评论，每篇最多保存 60 个节点、向下 4 层。B站会尝试最多 3 页顶层评论，最多跟进 5 个高赞楼中楼线程，每视频最多保存 60 个评论和回复节点。HN 每条故事最多 60 个评论节点、向下 4 层；GitHub 每个 issue/PR 最多保存 60 条讨论，评论页最多 2 页；V2EX 每个主题最多保存 60 条回复；Stack Overflow 每题最多 10 个答案、60 条评论。V2EX 公开 API 返回平铺回复；Stack Overflow 评论可以指向用户，但 API 不提供评论之间的父子 ID。各类富化使用剩余 `--budget` 并保留已取得的部分内容，每条记录带覆盖状态和截断原因。B站一次匿名样本显示旧评论接口后续页为空且总数不一致，结果会标为 partial；CSDN 一次匿名样本返回了博客正文和内嵌回复，但评论分页计数仍需继续观察。单样本不能代表持续在线成功率或全量覆盖。

## 本轮已修正

### 已取得的评论可以再检索

HTTP 和浏览器采集行中已有的 `comments`、`replies`、`answers` 会转换成社区 `Section`，保留作者、定位符、原生编号、父回复编号以及实际取得的点赞和时间字段。正文与讨论都进入全文检索；评论不进入作者声明取证索引。旧分隔标记格式仍能正确分层。

回复关系目前保存在 `Section.meta`，尚未建立独立评论对象与版本表。此次修正针对新入库材料，不会自动重写真实历史资料库。

B站现有评论正文与接口返回的嵌套回复会保留；显式富化时还会尝试追加评论页及最多 5 个楼中楼线程。CSDN 可从搜索命中跟进博客正文、评论分页和 API 已返回的嵌套回复。接口报告数与分页结果不一致时，两者都会保留 `discussion_coverage` 并标记 partial。当前仍是有限的讨论采样，不能声称取得全部评论和回复。

### 补正文保持来源与分层一致

直接回填、全量导入和仅正文缓存合并使用同一更新实现。更新会保留原来源元数据和讨论，维持原有主文的作者／社区、是否可取证等声明；无法确定作者角色的新正文只作为社区线索。

正文、分层、作者取证文本、指纹和可信度特征同步更新，FTS 由现有触发器更新；变化后的旧聚类标记会清除，后续聚类重算再归组。失败标记合并进原元数据，不覆盖来源信息。

缓存按每个编号的最后一条正文判断重复，因此 A → B → A 也会保存最后的 A。损坏的单行缓存、非对象记录和未知编号不会阻止后续有效记录回填。该缓存供重建回放使用，不等同于面向调查引用的完整版本系统。

### 浏览器等待与资源控制

- 快速与普通模式维持 HTTP 路径，浏览器仍仅在 deep 模式和来源条件允许时使用。
- 三个平台共用运行、独立会话和检查点实现。同一平台配置使用进程互斥锁，不再删除浏览器自身锁文件；忙碌时返回 `profile_busy`。
- 默认无头运行。一个 worker 内多个关键词复用同一浏览器上下文，批次结束关闭；尚无跨查询常驻浏览器池。
- DOM 变化或搜索响应到达后即可继续，等待有上限；首次结果在滚动前提取。
- 每个成功批次原子保存检查点，各次调用使用独立输出目录。超时或失败时，已有有效资料会返回为 `partial`，而非被当作完整成功或全部丢弃。
- 超时停止自身 worker 及其后代进程：Windows 使用该 worker PID 的进程树，POSIX 使用独立进程组。清理失败记录 `cleanup_error`。资源清理有独立短宽限，可能使实际返回略晚于采集截止时间。

## 验证与剩余工作

验证使用隔离数据库、模拟平台响应和本机自建子进程，不操作真实账号与资料库；不据此宣称线上平台成功率、耗时或内存降低了某个比例。
