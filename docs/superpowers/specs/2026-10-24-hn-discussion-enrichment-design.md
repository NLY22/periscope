# HN 故事讨论树富化设计

## 目的

将当前 HN 故事搜索结果补成可检索的评论与回复树，让调查结果包含搜索 API 返回的故事资料之外的原始讨论，并保留父子关系与采集覆盖情况。

## 方案

复用 `TopicService` 的可选 `--enrich` 阶段。故事搜索行保留 Algolia `objectID`；HN 适配器通过官方公开 Firebase `/v0/item/{id}.json` 读取节点，并按 `kids` 遍历回复。选用此方案是因为它直接利用 HN 公布的树形数据，不需要模拟网页或用户登录。

## 范围与约束

- 仅富化 `hn_ai`、`hn_cn` 等故事行；独立 `hn_comments` 搜索行不重复扩展。
- 每条故事最多 60 个评论节点，最多向下 4 层，并发最多 8 个请求；遵守调用方总时限，超时保留已取得节点。
- 每个节点保留原生 ID、作者、时间、正文、`parent_id` 和子回复；正文保持在 community 层，不能进入作者主张取证层。
- 覆盖元数据记录声明评论数、取得数量、到达深度、是否截断及失败原因；未知计数不能当作完整采集。
- 复用现有运行分片、导入和 SQLite FTS 链路；不改变定期订阅采集、不改 Web/MCP 接线、不加入评论版本历史。
- 只访问 HN 官方公开 API，不使用账号凭据；不声称抓取全量评论。

## 成功标准

开启 `--enrich` 后，HN 故事行包含有父子关系的评论树和可解释的覆盖元数据；分片写入并入库后，正文可全文回查，回复仍归于 community 层；达到任何预算上限时结果明确标为部分采集。

## 外部接口依据

HN 官方 API 文档：<https://github.com/HackerNews/API>。文档说明故事/评论按 `/v0/item/<id>.json` 读取；条目用 `kids` 列出子项，评论的 `parent` 指向父节点。
